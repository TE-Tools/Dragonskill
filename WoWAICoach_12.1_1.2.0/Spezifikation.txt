# WoW AI Coach – Entwicklungsübergabe seit der letzten ZIP

## 1. Projektziel

Entwickelt werden soll ein World-of-Warcraft-Retail-Addon für **WoW 12.1 / Midnight**, das sich wie ein persönlicher WoW-Coach verhält.

Der zentrale Unterschied zu einem klassischen Addon:

Der Spieler soll **frei im Spiel mit dem Coach chatten können**.

Beispiele:

- „Welche Items sollte ich noch austauschen?“
- „Was ist momentan mein größtes Upgrade?“
- „Welche Ini bringt mich am schnellsten weiter?“
- „Ich habe 30 Minuten, was soll ich machen?“
- „Ich habe 2 Stunden, welche Route ist am effektivsten?“
- „Welche Skillung soll ich nehmen?“
- „Welche Stats sind für meine Spec wichtig?“
- „Habe ich in meinen Taschen ein besseres Item?“
- „Wo bekomme ich mein nächstes Upgrade?“
- „Was soll ich als Nächstes machen?“
- „Warum ist dieses Item besser?“
- „Was sollte ich zuerst verbessern?“

Der Nutzer möchte **keine starre Auswahl von vorgegebenen Fragen**.

Das System soll freie Sprache verstehen.

---

# 2. Grundentscheidung: Lokale KI/Expert Engine

Eine externe KI soll **nicht zwingend erforderlich** sein.

Das Addon soll grundsätzlich auch ohne Internet und ohne API-Key funktionieren.

Deshalb:

```text
                 WoW AI Coach
                      │
          ┌───────────┴───────────┐
          │                       │
     LOCAL ENGINE             OPTIONAL KI
          │                       │
          │                       ├── eigener API-Key
          │                       └── eigener Proxy
          │
          ▼
      WoW-Daten
          │
          ▼
      Berechnung
          │
          ▼
      Empfehlung
```

Die lokale Engine ist die eigentliche Fakten- und Berechnungsschicht.

Die externe KI ist optional.

---

# 3. Warum die lokale Engine wichtig ist

Die externe KI darf nicht einfach selbst behaupten:

> „Dieses Item bekommst du aus Dungeon X.“

wenn das nicht aus unseren Daten stammt.

Die lokale Engine soll die Fakten liefern:

- aktuelles Gear
- Itemlevel
- Items
- Stats
- Spec
- Rollen
- vorhandene Items
- bekannte Lootquellen
- Dungeons
- Bosse
- Upgrade-Möglichkeiten
- Zeitaufwand

Die KI kann anschließend daraus eine natürliche Antwort formulieren.

Beispiel:

```text
Spieler:
Was soll ich verbessern?

Local Engine:
Trinket 1 = Upgrade Score 91
Ring 1 = Upgrade Score 82
Brust = Upgrade Score 51

KI:
Dein erstes Ziel sollte Trinket 1 sein.
```

---

# 4. API-Key-Konzept

Der Benutzer möchte ausdrücklich die Möglichkeit haben, **seinen eigenen API-Key direkt im Spiel einzugeben**.

Beispiel:

```text
/wki settings
```

Danach:

```text
KI-Einstellungen

KI-Modus:

● Lokale Engine
○ Eigener API-Key
○ Eigener Server

Provider:
OpenAI

API-Key:
[ ************************ ]

[ Verbindung testen ]
[ Schlüssel löschen ]
```

Der Benutzer soll seinen eigenen Key eingeben können.

Der Key darf:

- nicht im Quellcode stehen
- nicht in GitHub stehen
- nicht in die veröffentlichte ZIP eingebaut werden
- nicht an den Entwickler übertragen werden

Der Benutzer soll den Key selbst verwalten können.

## Wichtige Sicherheitswarnung

Ein WoW-Addon läuft auf dem Client.

Deshalb kann ein API-Key, der clientseitig gespeichert wird, technisch niemals vollständig geheim gehalten werden.

Das Addon soll deshalb beim Aktivieren anzeigen:

> Ein API-Key, der auf dem eigenen Rechner gespeichert wird, kann von Software oder Personen mit Zugriff auf den Rechner grundsätzlich ausgelesen werden. Für maximale Sicherheit wird ein eigener Proxy/Server empfohlen.

Für eine öffentliche Version ist daher vorzusehen:

```text
WoW Addon
   ↓
eigener Proxy
   ↓
OpenAI
```

Der echte OpenAI-Key liegt dann nur auf dem Server.

# 5. Modi

Es sollen drei Modi existieren.

## MODE 1 – LOCAL

Kostenlos.

Keine externe KI.

Keine API.

Keine Cloud.

Die lokale Expert Engine beantwortet Fragen.

---

## MODE 2 – OWN API KEY

Der Spieler verwendet seinen eigenen API-Key.

Der Key wird lokal konfiguriert.

Der Spieler trägt die API-Kosten selbst.

Dieser Modus ist optional.

---

## MODE 3 – OWN SERVER

Für eine spätere öffentliche Version.

Architektur:

```text
WoW AI Coach
      ↓
TE-WoW-Coach-Proxy
      ↓
OpenAI API
```

API-Key nur auf dem Server.

# 12. Item Score

Es soll ein interner Upgrade Score entwickelt werden.

Grundidee:

```text
ItemScore =
    ItemlevelScore
  + StatScore
  + SpecScore
  + SetBonusScore
  + SpecialEffectScore
  + UpgradePotential
```

Wichtig:

Itemlevel darf NICHT automatisch alles dominieren.

Ein Item mit höherem Itemlevel kann je nach Spec schlechter sein.

# 16. Keine erfundenen Lootdaten

Das ist eine harte Regel.

Wenn das Addon nicht weiß, wo ein Item erhältlich ist:

NICHT:

> „Das bekommst du wahrscheinlich aus Dungeon X.“

Sondern:

> „Für dieses Item ist momentan keine verifizierte Lootquelle in meiner Datenbank vorhanden.“

Datenstatus soll erkennbar sein.

---

# 17. Dungeon Optimizer

Die Frage:

> „Welche Ini bringt mich am schnellsten weiter?“

soll nicht einfach mit der höchsten Itemlevel-Belohnung beantwortet werden.

Berechnung soll berücksichtigen:

```text
Upgrade Value
×
Relevanz
×
Drop-Wahrscheinlichkeit
×
Zeitaufwand
```

Zusätzlich:

- benötigter Slot
- möglicher Boss
- vorhandenes Gear
- Ziel des Spielers
- verfügbare Zeit

---

# 18. Zeitoptimierung

Spieler kann fragen:

> „Ich habe 30 Minuten.“

oder:

> „Ich habe 45 Minuten.“

oder:

> „Ich habe zwei Stunden.“

Das System soll daraus einen Plan erzeugen.

Beispiel:

```text
30-MINUTEN-PLAN

1. Dungeon X
   Grund:
   mögliches Trinket-Upgrade

2. Falls kein Drop:
   Dungeon Y

3. Vorhandenes Taschen-Upgrade ausrüsten
```

Bei 2 Stunden kann der Plan anders aussehen.

# 20. Intent-Erkennung

Der freie Chat soll Fragen klassifizieren.

Beispiele:

```text
„Welche Items brauche ich?“
→ gear

„Welche Ini soll ich laufen?“
→ dungeon

„Welche Skillung?“
→ talent

„Welche Stats?“
→ stat

„Habe ich in den Taschen was Besseres?“
→ inventory

„Was soll ich jetzt machen?“
→ plan

„Welches Item ist besser?“
→ compare
```

Mehrere Intents können gleichzeitig auftreten.

Beispiel:

> „Welche Ini soll ich laufen, damit ich mein Trinket schnell verbessern kann?“

→

```text
dungeon
+
gear
+
item_farm
+
time_optimization
```

# 21. Gesprächskontext

Der Chat soll sich auf vorherige Antworten beziehen können.

Beispiel:

Spieler:

> Was soll ich verbessern?

Coach:

> Dein Trinket ist momentan dein größtes Upgrade.

Spieler:

> Wo bekomme ich das?

Coach:

> Aus Dungeon X.

Spieler:

> Und danach?

Coach:

> Danach würde ich Ring 1 verbessern.

Dafür muss der Kontext strukturiert gespeichert werden.

Nicht nur als Text.

Beispiel:

```lua
context = {
    currentGoal = "gear_progress",
    recommendedItem = itemID,
    recommendedSlot = 13,
    recommendedDungeon = dungeonID,
    nextPriority = itemID2
}
```

# 30. KI-Antwort

Die Daten kommen aber von der Engine.

# 43. Hauptprinzip des gesamten Projekts

Das wichtigste Ziel lautet:

**Nicht einfach eine KI in WoW einbauen.**

Sondern:

**Einen datengetriebenen WoW-Experten bauen, mit dem man wie mit einer KI sprechen kann.**

Die lokale Engine kennt die Fakten.

Die Optimierungsengine berechnet die beste Möglichkeit.

Der Chat macht die Interaktion natürlich.
